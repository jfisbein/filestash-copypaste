# copypaste — Copy, Cut and Paste for Filestash

[![CI](https://github.com/jfisbein/filestash-copypaste/actions/workflows/ci.yml/badge.svg)](https://github.com/jfisbein/filestash-copypaste/actions/workflows/ci.yml)

A runtime plugin for [Filestash](https://github.com/mickael-kerjean/filestash) that adds **Copy**,
**Cut** and **Paste here** to the files page, also **between Samba shares**, and makes
**drag-and-drop moves between shares** work.

Filestash has no copy at all, and its Samba backend refuses to move anything from one share to
another (`Not Implemented`). This plugin does both in the browser, through Filestash's own API, so
it needs no change to Filestash and no extra service.

> [!NOTE]
> **This code was written with AI.** The plugin, its tests, the CI and this documentation were
> written by Claude (Anthropic's model, through Claude Code), directed, reviewed and tested by
> Joan Fisbein. The translations were also generated by the model and **have not been reviewed by
> native speakers**: corrections are very welcome, see [Translations](#translations).

## What it does

- **Copy**, **Cut** and **Paste here** buttons in the files toolbar, and **Ctrl/Cmd+C, X and V**.
  Copy and Cut appear when something is selected; *Paste here* (or *Move here*, after a cut) in any
  folder while the clipboard holds something. The clipboard is shared by every tab of the same
  browser, so you can copy in one tab and paste in another. Cut items are dimmed.
- **Drag and drop between shares**: drop a file or folder on a folder of another share, in the list,
  in the sidebar tree or on the breadcrumb, or into another tab showing another share.
- **A move is the backend's own rename whenever it can be**: instant, and it keeps the dates. Only
  what the backend refuses to rename (Samba across shares) is copied and then removed from the
  source. That kind of move always asks first.
- **It never overwrites**: a name already taken in the destination gets a suffix,
  `report (copy).pdf`, `report (copy 2).pdf`, in the user's language.
- **Progress and cancel** in the toolbar: files, bytes and speed. Cancelling removes the file that was
  half-written.
- **In every language Filestash ships**, chosen the same way Filestash chooses its own.

## Requirements

- **Filestash with runtime plugins**: plugins are zips in the `plugins` folder of Filestash's state
  directory (`/app/data/state/plugins` in the Docker image), loaded at start. This one uses a
  `patch` module. It is tested against Filestash build `6463fe9` (2026-10-21), and the CI runs it
  every week against the latest `machines/filestash` image to catch upstream changes.
- **Any storage backend** should work, since the plugin only uses the files API (`ls`, `cat`, `save`,
  `mkdir`, `rm`, `mv`). It was written for, and is tested with, **Samba** behind the *passthrough*
  login, where each user signs in with their own Samba account and every share is a top-level folder.
- A current browser (Chrome, Edge, Firefox, Safari).

## Installation

1. Download `copypaste.zip` from the [latest release](https://github.com/jfisbein/filestash-copypaste/releases/latest)
   (its SHA-256 is published next to it).
2. Put it in Filestash's plugins folder. With Docker Compose, mount it read-only:

   ```yaml
   services:
     filestash:
       image: machines/filestash:latest
       volumes:
         - filestash_state:/app/data/state
         - ./copypaste.zip:/app/data/state/plugins/copypaste.zip:ro
   ```

3. Restart Filestash (plugins are read at start), then reload the page in the browser.
4. Optionally, check the installation. This needs no login:

   ```sh
   test/served-check.sh https://files.example.com/    # from a clone of this repository
   ```

   It checks that the patch is applied, that the plugin's files are served, and that everything
   the plugin relies on in Filestash is still there. **Run it again after every Filestash update.**

**To remove it**, delete the zip (or the volume line) and restart Filestash.

## How copying and moving behave

- **The data goes through the browser.** Each file is downloaded (`GET /api/files/cat`) and uploaded
  again (`POST /api/files/save`). Files up to 32 MiB are sent in one request; bigger ones are
  streamed as 32 MiB TUS chunks, so memory stays around one chunk. The speed is that of the browser's
  link, both ways: a copy on a LAN is fast, one over a slow VPN is not. Keep the tab open until it
  finishes. The page warns you if you try to close it.
- **A copy is a new file**: it gets the current date and the permissions the destination gives new
  files, like any upload. A move inside one share is a rename, so it keeps everything.
- **Every byte count is checked** against the source listing. A file that changed during the copy,
  or that the server rewrote on download (Filestash's SVG protection empties SVG files containing
  "entity"), fails loudly instead of being copied wrong.
- **A move across shares never loses data.** The copy is made first. Only when all of it has
  succeeded, the source files are deleted one by one, and then each source folder, only if it is
  empty by then. Anything added to the source during the copy stays there. A cancelled or failed
  move deletes nothing.
- **A whole share can't be moved** that way (it would be emptied). Copying a whole share is fine.
- Copies of more than 2,000 files or 10 GiB ask for confirmation first.

## Translations

The plugin speaks every language Filestash ships: Azerbaijani, Basque, Belarusian, Bulgarian,
Catalan, Chinese (simplified and traditional), Croatian, Czech, Danish, Dutch, English, Estonian,
Finnish, French (France and Canada), Galician, Georgian, German, Greek, Hungarian, Icelandic,
Indonesian, Italian, Japanese, Korean, Latvian, Lithuanian, Mongolian, Norwegian, Polish, Portuguese,
Romanian, Russian, Serbian, Slovak, Slovenian, Spanish, Swedish, Thai, Turkish, Ukrainian and
Vietnamese. It picks the language exactly as Filestash does, from the browser's language, and falls
back to English.

Each language is one file, [`src/locales/<lang>.json`](src/locales), keyed like
[`en.json`](src/locales/en.json). A message with a count has one entry per plural form of its
language (`one`, `few`, `many`, `other`…, as in
[`Intl.PluralRules`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules)).
Placeholders such as `{{count}}` must stay as they are. **All of them are machine translations**,
not yet reviewed by native speakers. To fix one, edit the file and run `node test/locales.mjs`,
which checks the keys, the placeholders and the plural forms of every language.

## How it works

| File | Role |
|---|---|
| `src/ctrl_submenu.diff` | A one-line patch, with no context, at the top of Filestash's `ctrl_submenu.js`. All it does is load `copy.js` from the zip, so upstream changes to that file don't break it. If it ever stops applying, Filestash serves the original file and the buttons simply don't appear. |
| `src/copy.js` | The UI: its own box in the toolbar (put back by a `MutationObserver` when the page re-renders), the clipboard in `localStorage`, shortcuts, progress, and a capture-phase `drop` listener that takes over only the drops whose source and target are in different top-level folders. |
| `src/engine.js` | The copy and move logic, with no DOM: planning (unique names, refusing a folder into itself), the transfers, the clean-up after a cancel, and removing the sources after a move. |
| `src/i18n.js` | The language choice and the translations, with plural forms. |

Files inside a plugin zip are served with a 30-day cache, so `build.py` puts a hash of the
sources into every URL (`?v=…`): a new version reaches the browser at once.

## Development

```sh
python3 -I build.py               # → dist/copypaste.zip (reproducible: same sources, same zip)
node test/locales.mjs             # translations
node test/mock.mjs                # the engine, against an in-memory imitation of the files API
node test/ui.mjs [es-ES]          # toolbar, clipboard, shortcuts and drop logic, in any language
```

These need only Node 20 or newer and Python 3, with no dependencies. The integration test runs
the real thing in Docker: Filestash with the plugin, logging in to a throwaway Samba server with
two shares.

```sh
python3 -I build.py && ci/up.sh   # Filestash on http://localhost:8334/ (PORT=… to change it)
test/served-check.sh http://localhost:8334/
FILESTASH_USER=alice FILESTASH_PASSWORD=copypaste-ci-password \
  node test/e2e.mjs --base http://localhost:8334/ --shares one,two
ci/down.sh
```

`test/e2e.mjs` can also be pointed at your own Filestash. It only writes inside a
`.copypaste-test-<timestamp>` folder in the shares you name, and removes it at the end. It copies
real data (about 20 MiB), checks every byte with SHA-256, cancels a transfer halfway, and moves a
folder both across and within shares.

The [CI](.github/workflows/ci.yml) runs all of this on every push and every Monday against the latest
Filestash image. A `v*` tag publishes a release with the zip, once the tag matches the version in
`src/manifest.json`.
